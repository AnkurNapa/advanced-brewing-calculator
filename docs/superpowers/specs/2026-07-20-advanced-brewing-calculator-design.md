# Advanced Brewing Calculator — Design Spec

**Date:** 2026-07-20
**Status:** Approved (units = metric default w/ toggle; theme = reuse IBC)

## 1. Summary

A static web app that rebuilds the **Master Brewers Toolbox** (James Hackbarth / MBAA) — a
brewing recipe **formulation**, **specification**, and **compare** engine — as a modern,
client-side Next.js app. It is the "pro tier" companion to the Indian Brewing Calculator (IBC):
where IBC does metric water chemistry, this does the full recipe→OPSTD formulation engine.

Source of truth for behavior: the vault KB at
`/Users/ankurnapa/Documents/obsidian/MasterBrewers_Export/MasterBrewers_KB/`
— especially `04_Calculations_Reference.md` (the numeric engine) and `01_Functional_Spec.md`.

## 2. Stack & conventions (mirror IBC exactly)

- Next.js 14 static export (`output: 'export'`, `basePath` `/advanced-brewing-calculator` in prod).
- React 18, TypeScript strict, Tailwind (reuse IBC `tailwind.config.ts` — copper/parchment/ink tokens).
- Vitest + jsdom. @visx for charts. Path alias `@/*` → `./src/*`.
- Deploy: GitHub Pages → `ankurnapa.github.io/advanced-brewing-calculator`.
- Font: Archivo. Design language identical to IBC (light, copper accent). No dark mode in v1.

## 3. Architecture — three layers

### 3a. `src/lib/engine/` — pure calc engine (NO React/DOM)
Faithful TS port of BrewHelp Ch.3/4. **All internal math in BASE UNITS: pound, barrel, inch, °F.**
Files (each independently unit-tested):
- `units.ts` — base-unit convert: `toBase(value, unit)`, `fromBase(base, unit)` via `units` table
  (`BaseUnitPerUnit`, `BaseUnitInt`). Formula: `base = value*perUnit + intercept`.
- `gravity.ts` — `lbbl(Plato)`, `P(lbbl)` (Newton, ≤20 iters, tol 1e-5), `fSGE(plato,d,t)`,
  `fSGA(alc,d,t)`, `dH2O(tempC)`, `bblwt(F)`, `REx(OG,dOG,RDF,dRDF,t)`, `ALx(...)`, `fAE(SG)`,
  `SGBeer(RE,ALC)`, `SGA60(abw)`. Polynomial coefficients transcribed verbatim from §15/§16.
- `extract.ts` — malt/grits/syrup/kräusen additions (§3), post-lauter tracking.
- `priming.ts` — priming syrups (§4), pre-primed OG, adjusted volume, beer RDF.
- `color.ts` — estimated SRM (§5).
- `hops.ts` — bittering & non-bittering additions (§6); measured utilization (§8);
  kinetic utilization (§9, Malowicki-Shellhammer: k1/k2, iso-alpha, gravity correction).
- `efficiency.ts` — brewhouse efficiency + back-calc iteration (§7).
- `rdfMash.ts` — mash RDF (§10) + estimated mash RDF (Brandam RK4 + regression fallback).
- `volumes.ts` — volumes worked back from fermenter (§11: whirlpool/trub/hopback/cool/KO/evap).
- `spec.ts` — Ch.4 spec engine (§13-19): RDF/OG/E-A/RDA/ADA, ABV, ash, calories, protein, carbs,
  color SRM↔EBC, distillation, refractive index.
- `water.ts` — residual alkalinity (§17), acid-addition RA.
- `blending.ts` — two-beer blend (§19: OGb, blended RDF/color/IBU/pH).
- `index.ts` — barrel export.

**Correctness gate — every engine PR must pass tests against these KB-worked numbers:**
`bblwt(172)=251.76`, `bblwt(64)`≈ per table, hop max isomerization **63.2% at 149 min**,
0-boil hop ≈16.7% isomerized, fermentation set **RE=4.771, ALC=4.269, OG=13.0, RDF=64.9**,
`k1=0.01249`, `k2=0.00309`, mash regression `estRDF = 36.78 + 0.3799*RDF − 0.1031*Color`.

### 3b. `src/lib/data/` — seed + repository
- `seed/*.json` — the 19 real tables (already generated by `scripts/build-seed.ts`). Read-only.
- `types.ts` — TS interfaces for every entity (Material, Formula, FormulaDetail, Plant, Product,
  Process, Unit, BaseUnit, Category, Transfer, Price, Loss, SFormula, SFormulaDetail, SMaterial,
  Blend). Mirror the DB columns exactly (see `02_Data_Model.md`).
- `repository.ts` — repository pattern. Reads seed first, overlays a localStorage patch layer
  (created/updated/deleted rows keyed by id). CRUD for formulas + support tables. Immutable
  updates (return new objects, never mutate). `useCatalog`-style hook wrapper in `src/hooks/`.
- `io.ts` — export all user data to a JSON file; import/merge from a JSON file.

### 3c. `src/app/` + `src/components/` — three modules (mirror the Switchboard)
- `/` — landing/switchboard: cards to the three modules + support tables, with a real recipe loaded.
- `/formulation` — recipe manager: pick/create Formula (Plant+Product+Date); parameter-line subform
  grouped by Process step (ordered by ProcessOrder then Stage); Calculate Forward / Backward;
  header targets (efficiency, volumes, OG, SRM, IBU, RDF) auto-derived; OPSTD report view (printable).
- `/specification` — spec form + the Ch.4 derivation engine (pick two analyses, derive the rest).
- `/compare` — diff a Formula vs its Spec using the 13 CompareFormSpec mapping rules.
- Support-table editors: materials, plants, products, units (reachable from landing).
- Global: unit-system toggle (Metric default ⇄ US) in the header; persists to localStorage.

## 4. Build phases (agent waves)

1. **Engine + tests** (critical path) — port every equation, TDD against §3a gate numbers.
2. **Data layer** — types + repository + localStorage overlay + import/export (parallel with engine).
3. **App shell** — layout, nav/switchboard, unit toggle, theme (parallel with 1/2).
4. **Formulation module** — depends on 1+2+3.
5. **Specification module** — depends on 1+2+3.
6. **Compare module** — depends on 4+5.
7. **Integrate + deploy** — build, fix, GitHub Pages.

## 5. Testing

- TDD on `src/lib/engine/**` and `src/lib/data/**`; 80%+ coverage (vitest `include: src/lib/**`).
- Engine tests assert the exact KB-worked numbers (§3a gate).
- UI: light smoke tests (renders, loads a seeded recipe, calculate updates a header value).

## 6. Non-goals (v1)

- No backend/auth/multi-user. No print-server PDF (browser print-to-PDF only). No i18n (English).
- No mobile-native build. Charts limited to what clarifies the OPSTD (gravity/color/IBU bars).

## 7. Key risks

- **Engine fidelity** is the whole ballgame. Mitigation: TDD against KB numbers + adversarial verify.
- **Backward calc** (zero formulation values → forward) is subtle; test both directions on a seeded recipe.
- Seed data has nulls/legacy quirks; repository must tolerate them (already numeric-coerced in seed).
